Merging Branch

Here’s a complete and practical explanation of merging branches in Git 🔀🚀
This is a very important concept (especially for projects & interviews).

🔹 What is Branch Merging?

👉 Merging means combining code from one branch into another

📌 Example:

You created a feature branch

Now you want to add it to main

📊 Visual Understanding
main ────────●────────●
              \
               ●──●──●  (feature-login)

👉 After merge:

main ────────●────────●────●
🔰 Step-by-Step Merge Process
✅ 1. Check current branch
git branch
✅ 2. Switch to main branch
git checkout main
✅ 3. Merge feature branch
git merge feature-login

👉 This will combine the code

✅ 4. Push to GitHub
git push origin main

👉 Upload merged code to GitHub

🔁 Full Example
git checkout -b feature-login
# write code
git add .
git commit -m "added login"

git checkout main
git merge feature-login
git push
🔀 Types of Merge
🔹 1. Fast-Forward Merge

👉 When no new commits in main

📌 Simple merge, no extra commit

🔹 2. 3-Way Merge

👉 When both branches have changes

📌 Creates a merge commit

⚠️ Merge Conflicts (Important 🚨)

👉 Happens when:

Same file edited in both branches

Example:

main → login button
feature → login form
🛠️ How to Fix Conflict

Git shows conflict in file

Open file → you’ll see:

<<<<<<< HEAD
your code
=======
other branch code
>>>>>>> feature-login

Edit manually

Save file

Run:

git add .
git commit -m "resolved conflict"
🧠 Real Workflow (Team Use)

Create branch

Work on feature

Push branch

Create Pull Request on GitHub

Merge after review

⚠️ Common Mistakes

❌ Merging wrong branch
❌ Not pulling latest code before merge
❌ Ignoring conflicts

🎯 Best Practices

✅ Always pull before merging
✅ Use meaningful branch names
✅ Delete branch after merge

git branch -d feature-login
🔥 Simple Meaning
git merge = "combine two branches into one"
🚀 Pro Tips

Use branches for every feature

Merge frequently to avoid conflicts

Test code after merging
