What is State in MERN?
In the MERN Stack
(MongoDB + Express.js + React.js + Node.js),

the word State is mostly used in React.js.

State means:

A variable that stores changing data in a component.

When data changes, React automatically updates the UI (screen).

Real-Life Example of State
Imagine a counter app.

Count = 0
When user clicks button:

Count = 1
The value changed.

This changing value is called State.

Why State is Important?
State helps React:

Store dynamic data

Update UI automatically

Handle user interaction

Create interactive applications

Without state, websites become static.

Example Without State
let count = 0;

function increase() {
  count++;
  console.log(count);
}
Problem:

UI will NOT update automatically.

Example With State
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h1>{count}</h1>

      <button onClick={() => setCount(count + 1)}>
        Increase
      </button>
    </div>
  );
}

export default Counter;
Now UI updates automatically.

Understanding useState()
const [count, setCount] = useState(0);
This line creates state.

Breakdown
Part	Meaning
count	Current value
setCount	Function to update value
useState(0)	Initial value = 0
Syntax of State
const [stateName, setStateName] = useState(initialValue);
Example:

const [name, setName] = useState("Aamir");
How State Works
Step 1: Create State
const [age, setAge] = useState(20);
Step 2: Show State
<h1>{age}</h1>
Step 3: Update State
setAge(25);
React re-renders component automatically.

Types of State in React
1. Primitive State
Stores:

string

number

boolean

Example:

const [age, setAge] = useState(22);

2. Object State
const [user, setUser] = useState({
  name: "Aamir",
  age: 22
});
Update object:

setUser({
  ...user,
  age: 23
});



3. Array State
const [items, setItems] = useState([]);
Add data:

4. Boolean State
Mostly used for:

toggle

dark mode

login/logout

popup open/close

Example:

const [dark, setDark] = useState(false);
Toggle:

setDark(!dark);
State vs Props
State	Props
Mutable	Immutable
Changes data	Receives data
Managed inside component	Passed from parent
useState used	Parent sends props

  return (
    <>
      <h1>{props.name}</h1>

    </>
  );
}




Rules of State

1. Never Change State Directly ❌
Wrong:
count = count + 1;

Correct:
setCount(count + 1);

2. State Updates are Asynchronous
Wrong expectation:

setCount(count + 1);
console.log(count);
Old value may print.

Correct Way
setCount((prev) => prev + 1);
Functional Update
Best when updating previous value.

setCount((prevCount) => prevCount + 1);

Complete Counter Example
import React, { useState } from "react";

function Counter() {

  const [count, setCount] = useState(0);

  const increase = () => {
    setCount(count + 1);
  };

  const decrease = () => {
    setCount(count - 1);
  };

  return (
    <div>

      <h1>{count}</h1>

      <button onClick={increase}>
        Increase
      </button>

      <button onClick={decrease}>
        Decrease
      </button>

    </div>
  );
}

export default Counter;

Storing and Using Session Info in Express
In Express.js sessions, we store user-specific data inside:

req.session
This data stays available across multiple requests.

What is Session Info?
Session info means:

user login data

cart items

username

theme

authentication status

Example:

req.session.user = "Aamir";
Basic Flow
User Login
    ↓
Store Data in Session
    ↓
Browser Gets Session ID Cookie
    ↓
User Makes New Request
    ↓
Server Reads Session Data
Step 1: Install Session Package
npm install express-session
Step 2: Setup Session Middleware
const express = require("express");
const session = require("express-session");

const app = express();

app.use(
  session({
    secret: "mysupersecret",
    resave: false,
    saveUninitialized: false,
  })
);
Step 3: Store Session Data
app.get("/login", (req, res) => {

  req.session.username = "Aamir";

  res.send("Session Data Stored");

});

   username: "Aamir"
}

  res.send(req.session.username);

Simple Definition
res.locals stores local variables that are available only during one request-response cycle.
