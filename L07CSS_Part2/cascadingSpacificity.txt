🧩 1. Cascading in CSS
🔹 What is Cascading?

Cascading means:

When multiple CSS rules apply to the same element, CSS decides which one will win.

CSS follows this priority order:

🧱 Cascading Order
1️⃣ Importance (!important)
2️⃣ Specificity
3️⃣ Source Order (last rule wins)

🧪 Example
p { color: blue; }
p { color: red; }


✔️ Result → red
Because last rule wins (source order).

🧪 With !important
p { color: blue !important; }
p { color: red; }


✔️ Result → blue
Because !important beats everything.

🎯 2. Specificity in CSS
🔹 What is Specificity?

Specificity is a scoring system that decides
which CSS selector is stronger.

Each selector has a weight:

Selector Type	Score
Inline style	1000
ID (#id)	100
Class / Attribute / Pseudo-class (.box, [type], :hover)	10
Element / Pseudo-element (div, p, ::before)	1
🧮 How to Calculate Specificity

Count each part:

Inline > ID > Class > Element

🧪 Example
#box p { color: blue; }
p { color: red; }


Specificity:

#box p → 100 + 1 = 101

p → 1

✔️ Result → blue (higher specificity wins)

🧪 Another Example
div.note p { color: green; }
#note p { color: orange; }


Specificity:

div.note p → 1 + 10 + 1 = 12

#note p → 100 + 1 = 101

✔️ Result → orange

🧠 Cascading vs Specificity (Together)

CSS decides like this:

1️⃣ !important
2️⃣ Highest specificity
3️⃣ Last written rule

🧪 Final Example
p { color: red; }
.note p { color: blue; }
#main p { color: green; }


Specificities:

p → 1

.note p → 11

#main p → 101

✔️ Result → green

🧾 Quick Interview Summary

Specificity	Strength of selector
!important	Overrides everything
Inline Style	Highest specificity
Last Rule	Wins when equal specificity

🧠 What is Specificity in CSS?

Specificity decides which CSS rule will apply when more than one rule targets the same element.

👉 Simply:

Higher specificity = stronger rule = it wins

🧮 Specificity Formula (Very Easy)

Think of it like a score:

Inline Style > ID > Class > Element


Each has a value:

Selector	Score
Inline style	1000
ID (#box)	100
Class (.card)	10
Attribute ([type])	10
Pseudo-class (:hover)	10
Element (div, p)	1
Pseudo-element (::before)	1
🧱 How to Calculate Specificity

Just add the values.

Example 1
#main p


#main → 100

p → 1
Total = 101

Example 2
div.card p:hover


div → 1

.card → 10

p → 1

:hover → 10
Total = 22

🏆 Which Rule Wins?

The one with the higher total.

p { color: red; }             /* 1 */
.box p { color: blue; }      /* 10 + 1 = 11 */
#main p { color: green; }    /* 100 + 1 = 101 */


✔️ Final color → green

🔥 Inline Style Beats Everything
<p style="color: purple;">Hello</p>


Inline = 1000
Nothing beats it (except !important).

💣 What About !important?

!important ignores all rules and forces itself to win.

p { color: red !important; }
#main p { color: green; }


✔️ Result → red

🧪 When Specificity is Equal?

Then last rule wins.

.box p { color: blue; }  /* 11 */
.box p { color: red; }   /* 11 */


✔️ Result → red (written later)

🧾 Quick Memory Trick

Think of this ladder:

!important
↓
Inline
↓
ID
↓
Class / Attribute / Pseudo-class
↓
Element / Pseudo-element


Higher on ladder = stronger

🧑‍💻 Real Life Tip

❌ Bad:

#header #menu .item a span { ... }


✔️ Good:

.menu-item { ... }


Simple selectors = easier to manage.

🌊 What is Cascading in CSS?

Cascading is the process CSS uses to decide
👉 which style rule will finally apply
when many rules target the same element.

🧠 Golden Rule of Cascading

When CSS is confused, it checks in this exact order:

1️⃣ !important
2️⃣ Specificity
3️⃣ Source Order (last written rule wins)


Memorize this as:

I → S → L
Important → Specificity → Last rule

🧪 How to Solve Any Cascading Question

Whenever you see multiple CSS rules, follow these 3 steps:

🥇 Step 1: Check for !important

If one rule has !important, it wins immediately.

p { color: red !important; }
#box p { color: blue; }


✔️ Answer → red

🥈 Step 2: Compare Specificity

If no !important, check which selector is stronger.

p { color: red; }         /* 1 */
.box p { color: blue; }  /* 11 */
#main p { color: green;} /* 101 */


✔️ Answer → green

🥉 Step 3: Check Last Rule

If both have same specificity, the last written rule wins.

.box p { color: blue; }
.box p { color: orange; }


✔️ Answer → orange

🧩 Full Example
p { color: red; }
.note p { color: blue; }
#main p { color: green; }
.note p { color: black !important; }

Solve:

1️⃣ !important found → .note p
✔️ Answer → black

🧾 One-Line Summary

First !important, then Specificity, then Last rule

🧠 Exam / Interview Trick

When you see a question, just ask yourself:

Any !important?

Which selector is strongest?

Which rule is written last?
