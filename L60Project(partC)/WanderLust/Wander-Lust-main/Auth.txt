Authentication vs Authorization in Easy Words
Authentication and Authorization are two important security concepts used in web applications like MERN apps, banking apps, social media apps, etc.

1. What is Authentication?
Authentication means:

"Who are you?"

It checks whether the user is real or not.

Example
When you login with:

Email

Username

Password

The system verifies your identity.

If correct → user logged in
If wrong → access denied

Real Life Example
ATM Machine
You insert ATM card

Enter PIN

Bank checks:

Is this really you?

This is Authentication.

2. What is Authorization?
Authorization means:

"What can you access?"

After login, system checks permissions.

Example
In a website:

User Type	Access
Student	View courses
Teacher	Upload courses
Admin	Delete users
All are authenticated users.

But permissions are different.

This is Authorization.

Authentication vs Authorization
Feature	Authentication	Authorization
Meaning	Verify identity	Verify permissions
Question	Who are you?	What can you do?
Happens First?	Yes	After authentication
Example	Login	Admin access
Uses	Password, OTP	Roles & permissions

   const token = req.headers.authorization;

   if(!token){
      return res.send("Unauthorized");

How Passwords Are Stored Securely
Passwords should NEVER be stored in plain text.

❌ Wrong:

Aamir123
If database gets hacked, all passwords become visible.

Correct Way → Hash Passwords
Passwords are stored using hashing.

What is Hashing?
Hashing converts a password into an unreadable string.

Example:

Password: Aamir123

Hashed Password:
$2b$10$K8sdfj2390sdfj0239sdlf...
You cannot easily convert hash back to original password.

↓

↓
Password gets hashed
↓
Hashed password stored in DB
Login Flow

↓
Server hashes entered password
↓
Compare with stored hash
↓
If match → Login success

Suppose database is hacked.

Without hashing:

admin123
hello123
With hashing:

$2b$10$asdasdasd...
$2b$10$kjhkjhkjh...
Hackers cannot directly read passwords.

what is hashing 

What is Hashing?
Hashing is a process that converts data into a fixed-size unreadable value called a hash.

It is mainly used for:

Password security

Data verification

Digital signatures

Blockchain

Authentication systems

Easy Definition
Hashing converts original data into a secret-looking string using a mathematical algorithm.

Example
Original Password:

hello123
After Hashing:

$2b$10$Xk92jshs8sksk282...
This unreadable string is called a hash value.

Important Point
Hashing is usually:

One-Way Process
Meaning:

Easy to create hash

Very hard to reverse back

Real Life Example
Imagine:

You put fruit into a grinder

Juice comes out

You cannot easily convert juice back into original fruit.

Hashing works similarly.

How Hashing Works
Original Data
↓
Hash Function
↓
Hash Value
Example in Password System
User Password
↓
Hashing Algorithm
↓
Store Hash in Database
Why Hashing is Used?
Because storing real passwords is dangerous.

Without Hashing
Database:

username: aamir
password: hello123
If hacked:

Password visible

With Hashing
username: aamir
password: $2b$10$asjdhajshd...
Now attacker cannot easily know original password.

Properties of Hashing
1. One-Way
You cannot easily reverse it.

Password → Hash
But:

Hash → Password ❌
2. Fixed Length
No matter input size, output length remains fixed.

Example:

hello
and

helloooooooooooooooooooo
Both generate fixed-size hashes.

3. Same Input = Same Hash
hello123 → abc456
hello123 → abc456
Always same output.

4. Small Change = Completely Different Hash
hello123
and

hello124
Produce totally different hashes.

What is Salting?
Salting means:

Adding a random value to a password before hashing it.

This random value is called a:

Salt
Why Salting is Needed?
Suppose two users use same password:

123456
123456
Without salt:

Both hashes become same

Example:

123456 → abc123
123456 → abc123
Hackers can guess common passwords easily.

With Salt
Random salt added before hashing.

Example:

Password = 123456
Salt = xYz12
Now hash becomes:

xYz12123456 → kjsd8923...
Another user:

Password = 123456
Salt = pQr78
Hash:

pQr78123456 → asd892ks...
Now both hashes are different.

Main Purpose of Salt
✅ Makes passwords more secure
✅ Prevents rainbow table attacks
✅ Prevents duplicate hashes
✅ Harder for hackers to crack passwords

Flow of Salting
Password
↓
Add Salt
↓
Hashing
↓
Store Hash
Real Example
Password:

hello123
Salt:

A1@x9
Combined:

hello123A1@x9
Then hashed.

Hackers keep pre-generated password hashes.

Example:

If your database stores same hashes:

hackers instantly know passwords.
